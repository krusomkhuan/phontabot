# เปิดใช้บันทึกคำถามและแจ้งสรุปเข้ากลุ่ม LINE

โค้ดบอทพร้อมเชื่อมต่อ แต่ยังไม่บันทึกจริงจนตั้งค่าครบ ห้ามใช้ไฟล์ FAQ สาธารณะเก็บคำถามผู้ใช้

1. เปิด https://script.google.com แล้วสร้างโปรเจกต์ใหม่ วางเนื้อหา Code.gs ในไฟล์ Code.gs
2. ใน Project Settings เปิดแสดงไฟล์ appsscript.json แล้วแทนด้วย appsscript.json ที่ให้มา
3. เลือกฟังก์ชัน setup แล้ว Run และอนุญาตสิทธิ์ด้วยบัญชีเจ้าของ งานนี้สร้างไฟล์บันทึกส่วนตัวใหม่ มีแท็บ “คำถามที่ยังตอบไม่ได้”, “สรุปรายวัน” และแท็บป้องกันนับซ้ำซึ่งซ่อนไว้ แชร์ไฟล์นี้เฉพาะผู้ดูแล ไม่เผยแพร่ CSV
4. Project Settings > Script properties จะมี LOG_SECRET และ LOG_SPREADSHEET_ID อัตโนมัติ ห้ามเปิดเผย LOG_SECRET
5. Deploy > New deployment > Web app เลือก Execute as: Me และ Who has access: Anyone ตัวรับตรวจลายเซ็นทุกคำขอ แม้ URL เปิดเข้าถึงได้ก็อ่านชีตไม่ได้ หากองค์กรไม่อนุญาต Anyone ต้องให้ผู้ดูแลระบบองค์กรจัดทางเลือก ไม่ใช้ลิงก์ /dev
6. คัดลอก URL ที่ลงท้าย /exec ไป Vercel ตัวแปร UNANSWERED_LOG_URL และคัดลอก LOG_SECRET ไป UNANSWERED_LOG_SECRET เลือก Production แล้ว Redeploy
7. เชิญน้องโพนต้าเข้า “กลุ่มช่วยเหลือน้องโพนต้า” และพิมพ์ /group-id ในกลุ่ม บอทตอบรหัสกลุ่มของกลุ่มนั้น (ไม่ผูกกลุ่มอัตโนมัติ)
8. ใน Script properties เพิ่ม ADMIN_GROUP_ID เป็นรหัสกลุ่ม และ LINE_CHANNEL_ACCESS_TOKEN เป็น token ของน้องโพนต้า เก็บค่าลับเฉพาะใน properties ไม่ใส่ในโค้ดหรือชีต
9. Run installDailySummary หนึ่งครั้ง จะตั้งส่งสรุปวันก่อนหน้าประมาณ 08:00–09:00 น. เวลาไทยทุกวัน ส่งเฉพาะวันที่มีเหตุการณ์และยังไม่ส่ง หากครั้งก่อนล้มเหลวจะพยายามส่งวันที่ค้างในรอบถัดไป ไม่ส่งข้อความรายคำถามเข้ากลุ่ม
10. ทดสอบถามข้อความนอก FAQ ซ้ำสองครั้งด้วยแชตส่วนตัว ตรวจว่าชีตเป็นแถวเดียว จำนวน 2; ถามคำถามที่มีคำตอบต้องไม่ถูกบันทึก จากนั้นทดสอบ sendDailySummary เมื่อมีข้อมูลวันก่อนหน้า (วันปัจจุบันจะยังไม่ส่ง)

## ให้ผู้ดูแลเพิ่มคำตอบจากกลุ่มลง Google Sheet FAQ

ต้องระบุบัญชีผู้ดูแลทีละคน ไม่ให้สิทธิ์ทุกคนที่อยู่ในกลุ่มโดยอัตโนมัติ

1. ผู้ดูแลแต่ละคนส่ง /my-id ในแชตส่วนตัวกับน้องโพนต้า จดรหัส U... ที่บอทตอบกลับ
2. ตั้ง ADMIN_USER_IDS เป็นรหัส U... ของผู้ดูแลที่ได้รับอนุญาต (คั่นด้วย comma หากหลายคน) ทั้งใน Vercel Production และ Script properties ค่าในสองที่ต้องตรงกัน ไม่ตั้งค่านี้เท่ากับปิดคำสั่งจัดการทั้งหมด
3. ตั้ง ADMIN_GROUP_ID เป็นรหัสกลุ่ม C... ที่เลือก ทั้งใน Vercel Production และ Script properties จากนั้น Redeploy Vercel
4. ตั้ง Script properties FAQ_SPREADSHEET_ID = 1z8s2vBfPcoiFlGaXLZYI8u0GBwTOBQ1x8dKl0MdOjjw และ FAQ_SHEET_ID = 0 บัญชีที่ Deploy Apps Script ต้องมีสิทธิ์แก้ไขไฟล์ FAQ เดิมด้วย ไม่เปลี่ยนสิทธิ์แชร์ไฟล์
5. ในกลุ่ม ผู้ดูแลที่ระบุไว้พิมพ์ /คำถามค้าง จะแสดง 5 คำถามที่มีคนถามบ่อย พร้อมรหัส 12 ตัว
6. เพิ่มคำตอบด้วย /ตอบ รหัส12ตัว | คำถามสำหรับ FAQ | คำตอบที่ตรวจสอบแล้ว ตัวอย่าง: /ตอบ abcdef123456 | มีเรียนภาคสมทบไหม | ข้อมูลที่เจ้าหน้าที่ตรวจสอบแล้ว
7. คำสั่งนี้เผยแพร่คำถามและคำตอบลงไฟล์ FAQ เดิมในหมวด เพิ่มเติมจากผู้ดูแล ให้พิมพ์คำถามกลางที่ไม่มีชื่อหรือข้อมูลส่วนบุคคล ไม่คัดลอกข้อมูลของผู้ถามไปโดยไม่ตรวจทาน ไม่รองรับเครื่องหมาย | ภายในคำถาม/คำตอบ
8. หากคำถามตรงกับแถวเดิมแต่คำตอบไม่ตรง ระบบจะไม่เขียนทับและไม่สร้างแถวขัดแย้ง ให้แก้ไขในชีตโดยตรง หากเป็นคำถามใหม่จะเพิ่มแถว FAQ และปรับสถานะบันทึกเป็น เพิ่มคำตอบแล้ว; หากการปิดสถานะล้มเหลวหลังเขียน FAQ ส่งคำสั่งเดิมซ้ำได้โดยไม่เพิ่มแถวซ้ำ
9. บอทอ่าน CSV ใหม่หลัง cache หมดประมาณ 60 วินาที และการเผยแพร่ CSV ของ Google อาจหน่วงเพิ่มได้ ห้ามเปลี่ยนชื่อหัวคอลัมน์สามช่องของ FAQ

คุยทั่วไปในกลุ่มจะไม่ถูกบันทึกเป็นคำถามค้าง บัญชีที่ไม่ได้ระบุไม่มีสิทธิ์ดูรายการหรือเพิ่ม FAQ ผ่านบอท หากสมาชิกผู้ดูแลเปลี่ยนให้อัปเดตรายการทั้งสองที่

## ข้อมูลที่เก็บ
วันเวลาครั้งแรก/ล่าสุด คำถาม จำนวนครั้ง สถานะ สาเหตุ และรหัสคำถาม ไม่เก็บชื่อ userId หรือโปรไฟล์ของผู้ถามทั่วไป ปิดบังอีเมลและตัวเลขยาวก่อนส่ง แต่ไม่สามารถตรวจจับข้อมูลส่วนบุคคลได้ทุกแบบ จึงต้องเก็บไฟล์เป็นส่วนตัว ส่วนคำสั่งผู้ดูแลส่งรหัสบัญชีผู้สั่งให้ตัวรับตรวจสิทธิ์ แต่ไม่บันทึกลงชีตคำถาม

คำถามซ้ำรวมตามข้อความที่ปรับอักษรเล็ก ตัดช่องว่าง/เครื่องหมาย ไม่ใช่การรวมทุกประโยคที่มีความหมายเหมือนกัน แยก no_match กับ system_error; เหตุการณ์ LINE เดิมไม่เพิ่มซ้ำด้วยรหัสเหตุการณ์ถาวรและเขียนตัวนับกับรหัสใน batch เดียว สถานะที่ผู้ดูแลปิดแล้วจะกลับมารออีกครั้งหากถูกถามซ้ำแต่บอทยังตอบไม่ได้

แก้สถานะในชีตบันทึกไม่ได้ทำให้บอทมีคำตอบ ต้องเพิ่มคำตอบที่ยืนยันแล้วในชีต FAQ เดิมด้วย รอ cache ประมาณ 60 วินาที ไม่ต้อง deploy เมื่อแก้ FAQ

หากบันทึกล้มเหลว บอทยังตอบผู้ใช้และบันทึกสถานะ failed ใน Vercel Logs โดยไม่แสดงคำถามหรือค่าลับ พยายามส่งซ้ำ 1 ครั้ง ไม่มีคิวถาวรฝั่ง Vercel จึงอาจสูญหายหากปลายทางล่มต่อเนื่อง; ตรวจ Logs และอีเมลแจ้ง trigger ล้มเหลวจาก Google ข้อความสรุป LINE ใช้โควตา push และระบุ retry key กันส่งซ้ำตามช่วงเวลาที่ LINE รองรับ

การเขียนข้อมูลผ่าน Sheets API ใช้สิทธิ์เจ้าของจาก Apps Script หากได้รับ API disabled ให้เปิด Google Sheets API ใน Cloud project ที่ผูกกับ Apps Script ก่อนทดสอบซ้ำ

ปริมาณมากควรย้าย event ledger ไปฐานข้อมูล และทำ retention ตามนโยบายวิทยาลัย; โค้ดนี้ไม่ลบประวัติอัตโนมัติ
